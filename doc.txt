Diese Dokumentation beschreibt die **implementierte** Architektur der Web-App vollständig genug, um sie als **native Android-App** nachzubauen. Sie ist bewusst code-nah: Konstanten, Algorithmen, Datenfelder und API-Verträge sind aus dem Quelltext übernommen.

## 1. Produktüberblick

NaviCircle ist ein **Navidrome-/Subsonic-Client** mit ungewöhnlicher, druckgrafisch inspirierter Oberfläche:

- Die Sammlung liegt **um ein Vinyl-Rad** herum; jedes Album/jede Playlist belegt ein Winkelstück, jeder Song eine eigene radiale Zeile.
- Vier Ansichten liegen auf einer **horizontalen Leinwand**: *Ganzes Rad* (Lyrics) → *Player-Nahaufnahme* → *Bibliothek* → *Einstellungen*.
- Metadaten kommen **aus Navidrome oder aus lokalen Dateien**; Audio wird **nur bei Wiedergabe** gestreamt, die nächsten vier Songs werden im Hintergrund vorgepuffert.
- Lyrics werden **zuerst aus der Datei/dem Server**, erst danach online gesucht.

### 1.1 Funktionsinventar (Ist-Stand)

| Bereich | Funktion | Verifikation |
| --- | --- | --- |
| Sammlung | Navidrome-Sync (Metadaten), Import lokaler Ordner inkl. Tags, CRUD für Künstler/Alben/Tracks/Playlists, Genre-Filter, Suche | `scripts/verify-library-ux.mjs` |
| Wiedergabe | Streaming, Play/Pause/Next/Prev, Seek, Shuffle, Repeat (off/all/one), Favoriten, Play-Count | `scripts/verify-readability.mjs` |
| Puffer | FIFO-Vorwärmung der nächsten 4 Songs, Cache 5, Abbrechen bei Sprüngen | `scripts/audio-cache.test.ts` |
| Rad | Drehen per Drag/Wheel/Tastatur, Snap pro Zeile, Vollkreis- und Nahansicht, sichtbares Fenster | `scripts/wheel-layout.test.ts`, `scripts/verify-wheel-hydration.mjs` |
| Lyrics | Datei/Server/Online, synchrone Zeilen, aktueller + 2 nächste, manueller Modus, Quelle sichtbar | `scripts/lyrics.test.ts` |
| Design | 5 Themes (`noir`, `light`, `midnight`, `salon`, `salon-light`), Salon mit Walnuss/Messing/Leder | `scripts/verify-club-ring.mjs`, `verify-club-themes.mjs` |
| Sprachen | Englisch, Deutsch, Albanisch – vollständig, inkl. Zahlen-Pluralformen | `scripts/verify-salon-settings.mjs` |
| Betrieb | SQLite-Datei, automatische Migration, Diagnoseseite statt Stacktrace, `/api/health` | `scripts/database.test.ts` |

## 4. Domänenmodell

Alle Tabellen liegen in **einer** SQLite-Datei (Standard `data/navicircle.db`, überschreibbar über `DATABASE_PATH`). Migrationen liegen in `drizzle/` und werden beim ersten Öffnen der Verbindung automatisch angewendet (`migrate()`), WAL-Modus, `foreign_keys = ON`, `busy_timeout = 5000`.

### 4.1 Entitäten und Beziehungen


### 4.3 Portierungshinweis

Das Schema ist **1:1 nach Room übertragbar** (SQLite-Dialekt identisch). Enums werden zu `@TypeConverter`/`enum class`, Booleans zu `INTEGER`, Zeitstempel zu `INTEGER (epoch millis)`.

## 6. Kernalgorithmen (reproduzierbar)

### 6.1 Rad-Geometrie (`src/lib/wheel-layout.ts`)

Alle Längen sind **Design-Einheiten** relativ zum Radmittelpunkt; gezeichnet wird in einem skalierten Container.

```ts
export const WHEEL = {
  disc: 230,       // Radius Vinyl
  text: 262,       // Radius Beschriftungsband
  progress: 300,   // Fortschrittsbogen
  rim: 356,        // Radius der Gruppenbögen
  item: 392,       // Abstand, an dem Zeilen beginnen
  extent: 388,     // halbe SVG-Kantenlänge
  visibleAngle: 74 // ±Grad im Nahmodus
} as const;

export const RHYTHM = { header: 96, track: 84, gap: 48 } as const;
```

Layout (einmal pro Bibliothek, **linear**):

```
cursor = 0
für jede Gruppe (Alben, dann Playlists):
  start       = cursor
  firstTrack  = start + headingUnits      // Salon: headingUnits = 0
  count       = max(tracks.length, album.trackCount)
  end         = firstTrack + count * RHYTHM.track
  cursor      = end + RHYTHM.gap
```

Zusätzlich wird `trackPositions[trackId] = firstTrack + i * track` gefüllt (für Auto-Drehung zur spielenden Zeile) und `maxPosition` aus der letzten Gruppe berechnet.

### 6.2 Sichtbares Fenster

Nur ein begrenzter Winkelbereich wird als DOM/SVG gerendert (Bibliotheken mit tausenden Alben bleiben flüssig).

```
degreesPerUnit = 180 / (π * WHEEL.item * closeScale)
rimAngle       = lerp(170°, 74°, zoom)      // Vollkreis → Nahansicht
start          = position - rimAngle / degreesPerUnit
end            = position + rimAngle / degreesPerUnit
```

Binärsuche findet die erste sichtbare Gruppe; danach werden Zeilen nur im Fenster erzeugt. Alle Winkel werden **relativ zu `position`** übergeben und auf 3 Nachkommastellen gerundet (`coordinate()`), damit Server- und Browser-Rendering identisch serialisieren (V8/SpiderMonkey unterscheiden sich sonst in den letzten Bits).

### 6.3 Snap und Tastaturschritte

- `snapPosition`: nächster Anker (Gruppenstart oder Zeilenposition) unter den Nachbargruppen.
- `stepPosition(±1)`: nächster Anker strikt größer/kleiner; an den Rändern stabil.
- Sichtbarkeit einer Zeile: `opacityAt(angle)` (Fade ab 78 % des sichtbaren Winkels) **×** `bandVisibility(angle)` (Fade an Timer/Transport).

### 6.4 Ring-Beschriftung (Salon)

`ringLabel(title, radius)` passt die Schriftgröße an die Bogenlänge an:

```
limit      = 0.93 * 2πr
charWidth  = font * 0.62 + 5
font       = clamp(floor((limit/len - 5)/0.62), 15, 32)
Rest passt nicht? -> Kürzen auf Platz bei 15 px, explizites „…“
```

Rendering: **ein** Titel auf einem Kreisbogen, der bei 12 Uhr beginnt (`M 0 -R A …`), `text-anchor="start"`, `startOffset="0%"`; die Gruppe rotiert per `<animateTransform from="0 0 0" to="360 0 0">` exakt um den Vinylmittelpunkt. Kontrast über `paint-order: stroke` mit `--bg`-Halo. Kein `textLength`/`lengthAdjust` (Firefox beschneidet Glyphen).

### 6.5 Audio-FIFO-Cache (`src/lib/audio-cache.ts`)

```
Klasse FifoAudioCache(capacity = 5)
  prefetch(currentKey, upcoming[4])
    1. protected = {current} ∪ upcoming
    2. nicht mehr benötigte, nicht-fertige Einträge abbrechen
    3. neue Ziele in Download-Warteschlange (FIFO)
    4. evict(): ältester nicht geschützter Eintrag zuerst
    5. pump(): genau EIN Download gleichzeitig
```

Details: `AbortController` je Download; abgebrochene Downloads halten ihren Slot bis zum `finally` (kein Overlap); nur echte Audio-Antworten werden gespeichert (JSON/HTML/404 nie); Fehler sind nicht fatal (dann Streaming); Object-URLs werden bei Eviction `revokeObjectURL`-t. `PREFETCH_AHEAD = 4`, Cache = 5. Bei `navigator.connection.saveData` wird nicht vorgepuffert.

### 6.6 Lyrics-Pipeline

**Parsing (`src/lib/lyrics.ts`)**
- LRC: `[mm:ss.xx]`, mehrere Zeitstempel je Zeile, `[offset:]` (ms, positiv = früher), Einfügen von Instrumentallücken, Sortierung, Deduplizierung gleicher Zeit.
- Reiner Text: `synced = false`, **nie** erfundene Zeitstempel.
- OpenSubsonic `structuredLyrics`: `start`/`offset` in **Millisekunden**, `start - offset` → Sekunden.
- Musikdatei: `music-metadata` → `common.lyrics` (SYLT/USLT/LYRICS/©lyr); SYLT wird nur bei `timeStampFormat = 2` (ms) als synchron übernommen, Frame-Nummern (1) gelten als unsynchronisiert.

**Auswahl (`src/lib/lyrics-service.ts`)**

```
1. tracks.embedded_lyrics vorhanden?           -> source = embedded
2. lokale Datei, lyrics_checked = 0            -> status = needs_file (Browser liest Tags, POSTet sie)
3. Navidrome: getLyricsBySongId.view
      sonst   getLyrics.view (Alt-Server)      -> source = navidrome
4. falls erlaubt: LRCLIB                        -> source = lrclib
5. sonst                                        -> not_found / unavailable
```

**Online-Matching (`src/lib/lyrics-online.ts`)**
- `GET https://lrclib.net/api/get` (track_name, artist_name, album_name, duration) → exakter Treffer, sonst **ein** `GET /api/search` (max. 20 Kandidaten).
- Akzeptanz nur bei normalisiert gleichem Titel **und** Künstler und `|duration − track.duration| ≤ 3 s`; Präferenz: gleiches Album → synced → nächste Dauer.
- Kein Audio, keine Navidrome-Zugangsdaten im Request; Timeout 6,5 s; Antwortgröße gedeckelt.
- `LYRICS_ONLINE_ENABLED=false` oder `settings.lyrics_source = file_only` deaktiviert Schritt 4.

**Cache**
- Fingerprint = SHA-256 aus Titel, Künstler, Album, Dauer, externalId, Online-Flag, Serveridentität.
- TTL: Treffer 7 Tage, „nicht gefunden“ 1 Tag; `unavailable` wird **nicht** gecacht.
- In-Flight-Deduplizierung pro Fingerprint, max. 3 parallele Lookups (Queue).

**Anzeige (`src/components/lyrics-panel.tsx`)**
- `lyricIndexAt()` = Binärsuche auf `time ≤ position` (funktioniert auch rückwärts/bei Pausen).
- Fenster = aktueller + 2 nächste Zeilen; Klick auf zeitgestempelte Zeile springt (`seekTo`).
- `settings.lyricsAutoscroll = off` friert die Zeile ein, Pfeiltasten bleiben nutzbar; unsynchronisierte Texte immer manuell.

### 6.7 Playback-Zeit ohne Re-Render (`src/lib/playback-clock.ts`)

Der Fortschritt liegt **nicht** im Player-Context, sondern in einem externen Store. Nur drei kleine Subscriber lesen ihn:

| Subscriber | Abonnement |
| --- | --- |
| Timer (`PlayerRegister`) | jede Sekunde |
| Fortschrittsbogen (`PlaybackProgressArc`) | jede Sekunde |
| Lyrics | **Zeilenindex** (nur bei Zeilenwechsel) |

Nachgewiesen im Browser-Test: Uhr läuft (10→14 Ticks), `PlayerContext`-Renders bleiben konstant (3→3). Beim Android-Port ersetzt `player.currentPosition` per `snapshotFlow { }` dieses Muster.

### 6.8 Leinwand/Zoom (`src/lib/canvas-store.ts`)

Vier Snap-Panels; der Rad-Bühnenknoten ist `sticky` und nimmt keine Breite ein. Beim Scrollen:

```
zoom  = clamp((scrollLeft - left0) / (left1 - left0), 0, 1)
shift = max(0, scrollLeft - left1)
span  = left2 - left1
```

`scale`, `cx`, `cy` werden zwischen Vollkreis- und Nahaufnahme-Rahmung interpoliert; `shift` verschiebt die Bühne mit den Panels und blendet sie ab 60 % aus. Vertikales Mausrad über dem Rad dreht — der Canvas fängt es non-passive ab, damit die Ansicht nicht springt.

### 6.9 Server-Erkennung (`src/lib/discover.ts`)

- Ermittelt IPv4-`/24`-Subnetze aller nicht-internen Interfaces (Fallback `192.168.1`).
- TCP-Probe auf `:4533`, `:443`, `:80`, Timeout 400 ms, 48 parallele Worker → sortiert nach Latenz.
- Anschließend Test per `ping.view` (Token-Auth, 2,5 s Timeout).

**Android-Hinweis:** TCP-Scan ist dort technisch möglich, aber Akku-/Policy-feindlich. Bevorzugt NSD/mDNS + manuelle Eingabe (siehe Android-Dokument).

### 6.10 Subsonic-Client (`src/lib/subsonic.ts`)

Token-Auth nach Spezifikation: `t = md5(password + salt)`, Parameter `u, t, s, v=1.16.1, c=NaviCircle, f=json`. Endpunkte: `ping`, `getArtists`, `getArtist`, `getAlbum`, `getPlaylists`, `getPlaylist`, `getLyricsBySongId`, `getLyrics`, `stream`, `getCoverArt`. Sync ersetzt ausschließlich `source = navidrome` und lässt lokale Importe unangetastet.

## 7. Client-Architektur (Web)

### 7.1 Komponentenbaum

```
app/layout.tsx (Dokument-Shell, ohne DB-Zugriff)
app/page.tsx (Server Component)
├─ liest DB (Alben, Künstler, Playlists, Tracks, Server, Settings)
├─ Bei DB-Fehler: <DatabaseSetup issue=…>
└─ <Providers initialSettings initialTracks initialAlbums …>
   ├─ QueryClient (Snapshots vorbefüllt → kein Nachladen)
   ├─ AppSettingsProvider (Sprache/Theme, `t()`, optimistisches PATCH)
   └─ PlayerProvider (Queue, isPlaying, shuffle, repeat, audioCache, PlaybackClock)
      └─ <DashboardApp>
         ├─ Canvas (4 Panels)
         │  ├─ PlayerPage  ← eine „Bühne“: Rad, Hub, Lyrics, Timer, Transport
         │  ├─ LibraryPage (lazy gemountet, memoized)
         │  └─ SettingsPage (lazy gemountet, memoized)
         ├─ PlayerRegister (der EINE Timer, über der Leinwand)
         └─ Punkte-Navigation (4 Snap-Punkte)
```

### 7.2 State-Regeln

| Zustand | Ort | Warum |
| --- | --- | --- |
| Serverdaten | React Query (`staleTime` 5 min) | Mutationen invalidieren gezielt |
| UI-Einstellungen | `AppSettingsProvider` | sofortige UI, PATCH im Hintergrund |
| Player (Queue, Flags) | `PlayerProvider` | nicht hochfrequent |
| Abspielzeit | externer `PlaybackClock` | verhindert Massen-Rerender |
| Radposition | lokaler State + `requestAnimationFrame` | 60 fps ohne React-Overhead |
| Canvas-Scroll/Zoom | `canvasStore` + `useSyncExternalStore` | nur das Rad hört zu |

### 7.3 Performance-Regeln (übertragbar)

1. Keine hochfrequenten Werte in großen Contexts.
2. Sichtbarkeitsfenster statt Vollrender; Serverseitig gerundete Geometrie.
3. Lazy Mount der Nicht-Player-Ansichten, danach memoized.
4. Indizes per `useMemo` (Alben→Tracks, Tracks je Künstler), Suche mit `useDeferredValue`.
5. Import in Batches (50 Dateien/POST, max. 3 parallele Tag-Reads).
6. Object-URLs erst bei Bedarf erzeugen.

## 9. Betrieb, Sicherheit, Grenzen

- **Start:** `npm install` → `npm run dev` (oder `build` + `start`). Erster Zugriff legt DB-Ordner, Datei und Tabellen an.
- **Diagnose:** DB-Fehler → Seite mit Klartext statt Stacktrace; `/api/health` liefert 503 + Code (`database_unavailable`, `database_read_only`, `database_corrupt`, `database_busy`, `database_full`, `database_driver_missing`, `database_schema_missing`). Keine Pfade/Passwörter in Antworten.
- **Sicherheit (Ist):** keine Benutzeranmeldung; Server-Passwort im Klartext in SQLite; SQLite-Datei daher schützen (git-ignored). Für Android: Keystore/EncryptedSharedPreferences.
- **Bekannte Grenzen:** kein Hintergrundabspielen im Browser, keine MediaSession, lokale Dateien nur innerhalb der Tab-Sitzung, Lyrics nur dreizeilig.
- **Datenhoheit:** Online-Lyrics senden ausschließlich Titel/Künstler/Album/Dauer.

# NaviCircle für Android — Architektur & Portierungsleitfaden

Ziel: eine **native Android-App** (Kotlin, Jetpack Compose), die sich funktional und gestalterisch wie die Web-App verhält, aber die Plattformvorteile nutzt: Hintergrundwiedergabe, MediaSession, echtes Offline-Caching, Keystore, Benachrichtigungen.

Grundlage: [`docs/ARCHITEKTUR.md`](./ARCHITEKTUR.md) (Ist-Stand) und [`docs/API-REFERENZ.md`](./API-REFERENZ.md).

## 1. Grundsatzentscheidungen

| Thema | Web (Ist) | Android (Soll) | Begründung |
| --- | --- | --- | --- |
| Datenhaltung | SQLite auf dem Server | **Room/SQLite auf dem Gerät** | Schema ist identisch; App wird autark |
| Navidrome-Zugriff | über Next.js-Proxy | **direkt** aus der App | Kein Server nötig; Zugangsdaten bleiben im Gerät |

## 5. Netzwerk & Streaming

### 5.1 Subsonic-Auth (Token, kein Klartext-Passwort)

```kotlin
data class SubsonicCredentials(val host: String, val port: Int, val https: Boolean,
                               val username: String, val password: String)

object SubsonicAuth {
  private const val V = "1.16.1"; private const val C = "NaviCircle"
  fun uri(creds: SubsonicCredentials, endpoint: String, params: Map<String, String> = emptyMap()): HttpUrl {
    val salt = ByteArray(8).also { SecureRandom().nextBytes(it) }.toHex()
    val token = md5(creds.password + salt)
    val base = (if (creds.https) "https://" else "http://") + creds.host + ":" + creds.port
    return "$base/rest/$endpoint".toHttpUrl().newBuilder().apply {
      addQueryParameter("u", creds.username); addQueryParameter("t", token)
      addQueryParameter("s", salt); addQueryParameter("v", V); addQueryParameter("c", C)
      addQueryParameter("f", "json"); params.forEach { (k, v) -> addQueryParameter(k, v) }
    }.build()
  }
}
```

**Wichtig:** Der Token ist zeitgebunden (Salt pro Request). Für ExoPlayer eine `ResolvingDataSource.Factory` verwenden, die die URI **beim Öffnen** neu signiert – niemals eine signierte URI lange zwischenspeichern.

### 5.2 Cleartext im Heimnetz

Android blockiert HTTP ab API 28. Navidrome im LAN läuft meist über HTTP. Lösung: `network_security_config.xml` mit `cleartextTrafficPermitted="true"` **nur** für private Bereiche, die der Nutzer explizit hinzufügt, oder generell für Debug; für Produktion besser HTTPS/Zertifikat empfehlen und in der UI warnen.

### 5.3 LRCLIB

`GET https://lrclib.net/api/get` (Fallback `/api/search`, max. 20 Kandidaten), Timeout 6,5 s, `User-Agent: NaviCircle/<version>` + `Lrclib-Client`-Header, Antwortgröße gedeckelt, Matching exakt wie in §6.6 der Architektur (Titel+Künstler normalisiert, Dauer ±3 s, Präferenz Album → synced).

### 6.2 Vorpuffern mit exakt derselben Semantik

Media3 bietet `DownloadHelper`/`DownloadManager`, doch die Web-Semantik ist enger. Empfohlen: **eigener** `PrefetchManager` mit `CacheWriter`, damit Kapazität 5, Vorlauf 4, FIFO-Eviction, Abbruch bei Sprüngen und „nur eine Datei gleichzeitig" garantiert bleiben:

```kotlin
class PrefetchManager(
  private val cache: SimpleCache,
  private val signer: (Track) -> Uri,          // Subsonic-URI, frisch signiert
  private val scope: CoroutineScope,
  private val capacity: Int = 5,
  private val ahead: Int = 4,
) {
  private val queued = ArrayDeque<Track>()
  private val ready = LinkedHashMap<String, Long>()   // Insertion-Order = FIFO
  private var protectedKeys: Set<String> = emptySet()
  private var job: Job? = null

  fun update(current: Track?, upcoming: List<Track>) {
    protectedKeys = (listOfNotNull(current) + upcoming).map { it.id }.toSet()
    queued.retainAll { it.id in protectedKeys }
    upcoming.filter { it.id !in ready && it.id != current?.id }
      .forEach { if (queued.none { q -> q.id == it.id }) queued.addLast(it) }
    evict()
    pump()
  }
  private fun evict() { /* ältester nicht geschützter Eintrag zuerst: cache.removeResource(span) */ }
  private fun pump() {
    if (job?.isActive == true) return
    val next = queued.removeFirstOrNull() ?: return
    job = scope.launch(Dispatchers.IO) { /* CacheWriter(signer(next), cache, DataSpec(signer(next))).cache() */ }
  }
}
```

Offline-Wünsche (Phase 2) laufen getrennt über `DownloadManager` und werden in Room markiert – sie dürfen von der FIFO-Eviction **nicht** gelöscht werden (`isPinned`-Flag im Cache-Index).

- `MediaSessionService` + `MediaSession` (PlaybackState, Metadata inkl. Artwork-URI).
- Audiofokus, `AudioManager.AUDIOFOCUS_LOSS_TRANSIENT` → pausieren, `becoming-noisy` → pausieren.
- Notification mit `MediaStyle` (API 33: `POST_NOTIFICATIONS` anfragen).
- `WAKE_MODE_NETWORK`, damit Streaming im Standby weiterläuft.

## 9. Server-Erkennung im LAN

1. **NSD/mDNS** (`NsdManager`, `_http._tcp` oder Navidrome-spezifisch): schnell, akkuschonend, benötigt `INTERNET` + ggf. `CHANGE_WIFI_MULTICAST_STATE` und ein `MulticastLock` während der Suche.
2. **Manuelle Eingabe** (Host/Port/Benutzer/Passwort) als immer verfügbarer Weg.
3. **Optionaler Subnetz-Scan** wie im Web (Ports 4533/443/80, 400 ms Timeout, ≤ 48 parallel) mit `Dispatchers.IO` + `Semaphore`, hartem Zeitlimit (~10 s), Abbruch bei Verlassen des Screens. Nur auf ausdrücklichen Nutzerwunsch starten (Akku, Play-Richtlinien), Ergebnis zusammen mit `ping`-Test anzeigen.
4. Zugangsdaten erst nach erfolgreichem `ping` speichern.

---

## 10. Synchronisation & lokale Dateien

- `NavidromeSyncWorker` (WorkManager, `CoroutineWorker`):
  - `getArtists` → je Künstler `getArtist` → je Album `getAlbum`;
  - Schreiben in einer Room-Transaktion (`withTransaction`), nur `source = navidrome` löschen;
  - Fortschritt über `setProgress`, Fehlerklassifizierung wie im Web (Netz, Auth, 5xx) mit `Result.retry()` + Backoff;
  - große Bibliotheken: `setForeground` mit Notification (Daten-Sync-Typ).
- Playlists optional in derselben Transaktion spiegeln.
- **Lokaler Import:** `ACTION_OPEN_DOCUMENT_TREE` + `DocumentFile`, Tags via jaudiotagger, Lyrics beim Import mitlesen (`lyrics_checked = 1`), Datei-URI im `local_key` (persistente URI-Berechtigung!), Audio über `content://` in ExoPlayer.
- Rechte: `READ_MEDIA_AUDIO` (API 33+) bzw. `READ_EXTERNAL_STORAGE` (≤ 32) nur, wenn der Nutzer importiert.

---

## 11. Einstellungen & Sicherheit

- **DataStore** speichert `language`, `theme`, `volume`, `lyricsAutoscroll`, `lyricsSource`; Room-`settings` bleibt als Backup-/Exportspiegel (Schema-kompatibel zum Web-Export).
- **Server-Passwort**: AES/GCM mit Keystore-Schlüssel (`setUserAuthenticationRequired(false)`), Ciphertext in Room; `allowBackup=false` oder Verschlüsselung vor Backup schützen.
- Keine Telemetrie; Online-Lyrics nur mit Titel/Künstler/Album/Dauer; Schalter „nur Datei/Server" (`file_only`) respektieren.
- Netzwerksicherheit: private Ziele als `domain-config` mit Cleartext; öffentliche Ziele nur HTTPS.

## 12. Performance-Regeln (aus den Web-Erkenntnissen)

1. `buildWheelLayout` als **reine, memoisierte** Funktion; nie in der Composition neu bauen.
2. Sichtbares Fenster begrenzen; keine 20 000 Composables.
3. `rotationZ` über `graphicsLayer` (GPU) statt Layout-Änderung.
4. Hochfrequenten Fortschritt isolieren (`snapshotFlow`, eigene Composables) – niemals im globalen `ViewModel`-State.
5. Bilder: Coil mit Disk-Cache, `crossfade(false)` im Rad, Graustufen im Salon optional.
6. Suche: `debounce(150 ms)`, Filterung auf bereits geladenen Listen.
7. Baseline Profile + `R8` für Startzeit; `SimpleCache` auf `cacheDir`.
8. Große Bibliothek: Sync in Batches, `Room`-Schreibvorgänge transaktional, UI liest `Flow` mit `distinctUntilChanged`.

## 5. Netzwerk & Streaming

### 5.1 Subsonic-Auth (Token, kein Klartext-Passwort)

```kotlin
data class SubsonicCredentials(val host: String, val port: Int, val https: Boolean,
                               val username: String, val password: String)

object SubsonicAuth {
  private const val V = "1.16.1"; private const val C = "NaviCircle"
  fun uri(creds: SubsonicCredentials, endpoint: String, params: Map<String, String> = emptyMap()): HttpUrl {
    val salt = ByteArray(8).also { SecureRandom().nextBytes(it) }.toHex()
    val token = md5(creds.password + salt)
    val base = (if (creds.https) "https://" else "http://") + creds.host + ":" + creds.port
    return "$base/rest/$endpoint".toHttpUrl().newBuilder().apply {
      addQueryParameter("u", creds.username); addQueryParameter("t", token)
      addQueryParameter("s", salt); addQueryParameter("v", V); addQueryParameter("c", C)
      addQueryParameter("f", "json"); params.forEach { (k, v) -> addQueryParameter(k, v) }
    }.build()
  }
}
```

**Wichtig:** Der Token ist zeitgebunden (Salt pro Request). Für ExoPlayer eine `ResolvingDataSource.Factory` verwenden, die die URI **beim Öffnen** neu signiert – niemals eine signierte URI lange zwischenspeichern.

### 5.2 Cleartext im Heimnetz

Android blockiert HTTP ab API 28. Navidrome im LAN läuft meist über HTTP. Lösung: `network_security_config.xml` mit `cleartextTrafficPermitted="true"` **nur** für private Bereiche, die der Nutzer explizit hinzufügt, oder generell für Debug; für Produktion besser HTTPS/Zertifikat empfehlen und in der UI warnen.

### 5.3 LRCLIB

`GET https://lrclib.net/api/get` (Fallback `/api/search`, max. 20 Kandidaten), Timeout 6,5 s, `User-Agent: NaviCircle/<version>` + `Lrclib-Client`-Header, Antwortgröße gedeckelt, Matching exakt wie in §6.6 der Architektur (Titel+Künstler normalisiert, Dauer ±3 s, Präferenz Album → synced).

### 6.2 Vorpuffern mit exakt derselben Semantik

Media3 bietet `DownloadHelper`/`DownloadManager`, doch die Web-Semantik ist enger. Empfohlen: **eigener** `PrefetchManager` mit `CacheWriter`, damit Kapazität 5, Vorlauf 4, FIFO-Eviction, Abbruch bei Sprüngen und „nur eine Datei gleichzeitig" garantiert bleiben:

```kotlin
class PrefetchManager(
  private val cache: SimpleCache,
  private val signer: (Track) -> Uri,          // Subsonic-URI, frisch signiert
  private val scope: CoroutineScope,
  private val capacity: Int = 5,
  private val ahead: Int = 4,
) {
  private val queued = ArrayDeque<Track>()
  private val ready = LinkedHashMap<String, Long>()   // Insertion-Order = FIFO
  private var protectedKeys: Set<String> = emptySet()
  private var job: Job? = null

  fun update(current: Track?, upcoming: List<Track>) {
    protectedKeys = (listOfNotNull(current) + upcoming).map { it.id }.toSet()
    queued.retainAll { it.id in protectedKeys }
    upcoming.filter { it.id !in ready && it.id != current?.id }
      .forEach { if (queued.none { q -> q.id == it.id }) queued.addLast(it) }
    evict()
    pump()
  }
  private fun evict() { /* ältester nicht geschützter Eintrag zuerst: cache.removeResource(span) */ }
  private fun pump() {
    if (job?.isActive == true) return
    val next = queued.removeFirstOrNull() ?: return
    job = scope.launch(Dispatchers.IO) { /* CacheWriter(signer(next), cache, DataSpec(signer(next))).cache() */ }
  }
}
```

Offline-Wünsche (Phase 2) laufen getrennt über `DownloadManager` und werden in Room markiert – sie dürfen von der FIFO-Eviction **nicht** gelöscht werden (`isPinned`-Flag im Cache-Index).

## 9. Server-Erkennung im LAN

1. **NSD/mDNS** (`NsdManager`, `_http._tcp` oder Navidrome-spezifisch): schnell, akkuschonend, benötigt `INTERNET` + ggf. `CHANGE_WIFI_MULTICAST_STATE` und ein `MulticastLock` während der Suche.
2. **Manuelle Eingabe** (Host/Port/Benutzer/Passwort) als immer verfügbarer Weg.
3. **Optionaler Subnetz-Scan** wie im Web (Ports 4533/443/80, 400 ms Timeout, ≤ 48 parallel) mit `Dispatchers.IO` + `Semaphore`, hartem Zeitlimit (~10 s), Abbruch bei Verlassen des Screens. Nur auf ausdrücklichen Nutzerwunsch starten (Akku, Play-Richtlinien), Ergebnis zusammen mit `ping`-Test anzeigen.
4. Zugangsdaten erst nach erfolgreichem `ping` speichern.

## 10. Synchronisation & lokale Dateien

- `NavidromeSyncWorker` (WorkManager, `CoroutineWorker`):
  - `getArtists` → je Künstler `getArtist` → je Album `getAlbum`;
  - Schreiben in einer Room-Transaktion (`withTransaction`), nur `source = navidrome` löschen;
  - Fortschritt über `setProgress`, Fehlerklassifizierung wie im Web (Netz, Auth, 5xx) mit `Result.retry()` + Backoff;
  - große Bibliotheken: `setForeground` mit Notification (Daten-Sync-Typ).
- Playlists optional in derselben Transaktion spiegeln.
- **Lokaler Import:** `ACTION_OPEN_DOCUMENT_TREE` + `DocumentFile`, Tags via jaudiotagger, Lyrics beim Import mitlesen (`lyrics_checked = 1`), Datei-URI im `local_key` (persistente URI-Berechtigung!), Audio über `content://` in ExoPlayer.
- Rechte: `READ_MEDIA_AUDIO` (API 33+) bzw. `READ_EXTERNAL_STORAGE` (≤ 32) nur, wenn der Nutzer importiert.

## 11. Einstellungen & Sicherheit

- **DataStore** speichert `language`, `theme`, `volume`, `lyricsAutoscroll`, `lyricsSource`; Room-`settings` bleibt als Backup-/Exportspiegel (Schema-kompatibel zum Web-Export).
- **Server-Passwort**: AES/GCM mit Keystore-Schlüssel (`setUserAuthenticationRequired(false)`), Ciphertext in Room; `allowBackup=false` oder Verschlüsselung vor Backup schützen.
- Keine Telemetrie; Online-Lyrics nur mit Titel/Künstler/Album/Dauer; Schalter „nur Datei/Server" (`file_only`) respektieren.
- Netzwerksicherheit: private Ziele als `domain-config` mit Cleartext; öffentliche Ziele nur HTTPS.

## 12. Performance-Regeln (aus den Web-Erkenntnissen)

1. `buildWheelLayout` als **reine, memoisierte** Funktion; nie in der Composition neu bauen.
2. Sichtbares Fenster begrenzen; keine 20 000 Composables.
3. `rotationZ` über `graphicsLayer` (GPU) statt Layout-Änderung.
4. Hochfrequenten Fortschritt isolieren (`snapshotFlow`, eigene Composables) – niemals im globalen `ViewModel`-State.
5. Bilder: Coil mit Disk-Cache, `crossfade(false)` im Rad, Graustufen im Salon optional.
6. Suche: `debounce(150 ms)`, Filterung auf bereits geladenen Listen.
7. Baseline Profile + `R8` für Startzeit; `SimpleCache` auf `cacheDir`.
8. Große Bibliothek: Sync in Batches, `Room`-Schreibvorgänge transaktional, UI liest `Flow` mit `distinctUntilChanged`.
